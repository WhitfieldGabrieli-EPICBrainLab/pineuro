# Changelog

All notable changes to pineuro will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.1.0] - 2026-10-28

### Added

- **The brain mask can be reviewed and adjusted after preprocessing.** A Review Brain Mask window opens when preprocessing finishes (and from a button under the step) and shows the mask outline on the unmasked mean EPI in several slices per plane. Its two settings are the intensity threshold (a fraction of the image mean, default 0.5) and the cleanup radius of `ants.get_mask` (default 2 voxels), which were hardcoded. Recompute previews a mask without writing anything; Accept with changed values recomputes only the brain mask, the masked timeseries and the BOLD reference, then deletes and re-runs that localizer's mask extraction and coregistration. Study defaults are set on the Localizer tab (a new optional `preprocessing:` block with `brain_mask_threshold_fraction` and `brain_mask_cleanup`, written only when changed), and `brain_extraction()`, `preprocessing()` and the new `recompute_brain_mask()` / `preview_brain_mask()` take them as keyword arguments. Each participant's values and sources are recorded in `{sub}_{ses}_task-{task}_preproc_mask.json`, and an operator's choice is reused when preprocessing is re-run.
- **Task (GLM) masks can be re-thresholded at review.** Each mask in Review & Approve Masks has an Adjust threshold panel with the localizer's own method parameters (cluster-forming threshold, minimum cluster size and cap for `cluster_extent`). Preview recomputes the mask from the saved GLM map without refitting the GLM and shows it in the overlay; Apply replaces it. `mask_selections.json` records the parameters used (`threshold_params`), the clusters found before the size filter (`n_clusters_input`, `largest_cluster_input`) and a `selection_reason` of `operator_rethreshold`.
- **Task localizers can have a fallback mask per contrast.** The Localizer tab's optional Fallback Masks section (`extraction.fallback_masks`) sets an atlas network (e.g. Yeo-17 DefaultA) or an MNI-space mask file per contrast, and the review offers Use fallback, plus Replace… for an atlas network, an MNI-space file, or a mask file already in the participant's space (such as a hand-edited copy of the mask, which is copied into `mask_edits/` so the record stays valid) chosen for one participant. MNI-space replacements are warped to the participant's space, and every replacement is saved under the contrast's mask name, so feedback uses it with no manual file changes.
- **Operator changes to task masks are reproducible.** They are saved in `mask_overrides.json`, passed to `mask_extraction_task(mask_overrides=...)` and written into `reproduce_masks.py`, so a replay on a clean tree recomputes the same masks; `update_task_mask()` applies one change from the cached GLM outputs.
- **A sham study's randomization file can be a list of pre-allocated slots that participants fill as they are scanned.** With a `slot` column (a new list has no `subject_id` column; pineuro adds it at the first assignment, and a blank `subject_id` marks an unused slot), starting a participant's first session assigns them the next unused slot in file order. The Start dialog names the slot and never the condition, and the participant's ID and an `assigned_at` time are written into the file, so it records the slot each participant received. Study IDs can therefore have gaps, for example from participants who withdraw before scanning, without unbalancing the list. For replay, `matched_slot` names the slot whose participant is replayed. The Generate Randomization dialog can create a slot list, `generate_randomization()` takes `slots=True`, and `next_unassigned_slot()` and `assign_next_slot()` are new in `pineuro.sham`. Files without a `slot` column work as before.

### Fixed

- **RIT no longer crashes on macOS at the end of the task.** After the task finished, the task process's stop-bridge thread could hold the last reference to the task at interpreter exit, so RIT's text stimuli were freed on that thread with no OpenGL context and the process segfaulted (`glDeleteLists`). The bridge now releases the task on the main thread when the step ends, and RIT deletes its stimuli before the window closes, as the other tasks do. Data were not affected; the crash happened after the events file was written.
- **A task mask with 0 voxels can no longer be approved.** It was marked complete and approvable, and feedback then failed when it loaded the mask. The review now flags it and blocks approval until it is re-thresholded or replaced.
- **The session-wide Use MNI Atlas Masks buttons are shown only for rest localizers.** For a task localizer they wrote masks named after atlas networks (`ContA`, `DefaultA`), which feedback could not match to the contrast's mask name.
- **Use Atlas Mask in the task mask review uses the reviewed localizer and records the change.** It read the first localizer's settings whatever was being reviewed, copied the file without updating `mask_selections.json`, and skipped the shared `03_masks` copy that coregistration reads with several localizers.
- **Re-running mask extraction with Skip Existing keeps each mask's recorded provenance** instead of overwriting it with a minimal entry.
- **The Harvard-Oxford cluster labels follow a new BOLD reference.** Their transform to MNI space was always reused, even with Overwrite, so labels could come from a stale registration.
- **The preprocessing QC report draws the brain mask on the unmasked mean EPI** (it used the masked BOLD reference, which hid brain the mask had cut off), and the brain-extraction docs describe `get_mask` correctly (it does no Otsu thresholding).
- **Replay sham finds the matched participant's feedback log.** The runner looked for it inside the current participant's folder (`<study>/<participant>/<matched participant>/<session>/...`), a leftover from the per-participant layout used before multi-session studies, so every replay feedback run stopped with "Feedbacklog not found for replay". It now looks in the study folder, as coregistration already did.
- **Generated replay randomizations pair each sham participant with a different, earlier real participant.** The generator matched sham to real participants round-robin regardless of list order, so most sham participants could be matched to a real participant later in the list, whose feedback log does not exist yet when the sham participant is scanned; their feedback run then stopped with "Feedbacklog not found for replay". The assignment is now drawn from the orders in which every sham participant has an unpaired real participant before them, and each sham participant is paired with the earliest one, so no real participant is replayed twice. A replay list can therefore be at most half sham. Files generated before this change keep their old matches, so regenerate them or check that every matched participant is scanned first.
- **Participant IDs with leading zeros are read verbatim from a randomization file.** IDs such as `001` were read as numbers (`1`), so a sham study that used them blocked those participants at session start as not listed.

## [1.0.0] - 2026-10-16

### Added

- **pineuro is on PyPI.** `pip install pineuro` installs it. The README and the installation guide now install from PyPI, the guide gains an Updating section and a note to install wxPython first on Linux (PyPI has no Linux wheels for it), and the README's links are absolute so that they work on the PyPI project page.

### Changed

- **The `dev` extra pins ruff and mypy exactly, and CI type-checks on Python 3.10.** `ruff==0.15.2` and `mypy==1.19.1` (and the same ruff in CI) replace `>=` floors, so a new release of either can no longer fail CI on unchanged code, as ruff 0.17 did by also formatting code blocks in Markdown files. Upgrading them is now a deliberate change, as it already is for antspyx and nilearn. CI's type-check job also moves from Python 3.11 to 3.10, the version mypy targets: on 3.11 it installed numpy 2.3, whose stubs do not support a 3.10 target, and mypy flagged a spurious `Any` return.

### Removed

- **`pineuro.gui.__version__` is removed.** It was hardcoded to `0.2.0`, never updated, and read by nothing; the version is `pineuro.__version__`, which comes from the installed package metadata.

### Fixed

- **The live brain-slice preview no longer flickers during acquisition.** Each volume's slice replaced the preview image, and Flet's `ft.Image` shows nothing while a new image source decodes (`gapless_playback` defaults to `False`), so the white page flashed between every two slices. Both previews, the Brain Slice in the localizer monitoring panel and the collection progress panel, now keep the previous slice on screen until the next one has decoded, as the Task Display mirror already did.

## [0.12.0] - 2026-10-14

### Breaking

- **RIT events files are now named per attempt and per task entity.** RIT Triggered Ball and RIT Experience Sampling wrote `{sub}_{ses}_task-<task id>_run-NN_events.tsv`, without the attempt and with the task id rather than the run's task entity. A re-attempt therefore overwrote the earlier attempt's events, `discard_attempt` left them behind, and a transfer run (task entity `<task>transfer`) overwrote the events of the feedback run with the same run number, while the feedback summary and QC report, which look under the transfer entity, never found the transfer run's episodes. Both tasks now use the feedback log's `{sub}_{ses}_task-<entity>_run-NN_attempt-NN` prefix (`…_events.tsv`), and both readers include the attempt. Files already written keep their old names; analysis scripts that glob the old pattern need updating.
- **The RIT ratings ask about unpleasantness instead of sadness, and their data fields are renamed.** The RIT localizer's post-rumination and post-distraction ratings now ask "How unpleasant did it feel to think about the topic?" and "How focused were you on your feelings?", both anchored "Not at all" / "Extremely" (previously "How sad do you feel right now?" and "How focused are you on your feelings?"), and the instruction slide says so. RIT Experience Sampling's first probe now asks "How unpleasant are your current feelings?" ("Not unpleasant" / "Very unpleasant"). The localizer's events trial types `rating_sadness_post_rumination` / `rating_sadness_post_distraction` are now `rating_unpleasantness_post_rumination` / `rating_unpleasantness_post_distraction`, and the Experience Sampling events columns `sadness_rating` / `sadness_rt` are now `unpleasantness_rating` / `unpleasantness_rt`. Data already collected keeps the old names; analysis scripts that read them need updating. The rumination and distraction prompts are unchanged.

### Added

- **Free-disk-space bar and a low-space check before acquisitions.** A bar along the bottom of the window shows free space on the volumes pineuro writes to: every study's data root on the Study Manager, and during a session that study's data root (plus the scanner's DICOM folder in real-time mode, when it sits on another volume). It refreshes every minute and after each step. On entering a session, pineuro estimates the space the session needs as the size of the largest previous session of the same study, computed off the UI thread; when free space is below that, the bar turns to a warning and starting an acquisition asks for confirmation. With no previous session there is no basis for a threshold, so nothing is flagged. The helpers live in the new stdlib-only `pineuro.storage` module.
- **Optional session backup.** A study can now copy each participant-session folder to `<backup folder>/<participant>/<session>`, configured in the Study tab (new top-level `backup: {enabled, destination, include_dicoms}` block, off by default). A pass runs after every successful step, when the operator leaves the session, and on **Back Up Now** in Session Utilities, always on a background thread and never during an acquisition: starting a step stops a pass at its next file, and the next pass resumes where it left off because only new or changed files (by size and modification time) are copied. Copies go through a temporary name, nothing at the destination is ever deleted, `tmp/` is never copied, and the raw DICOM copies in `collection/` can be left out. The backup folder must already exist, so a backup to a disconnected drive is reported instead of filling the local disk under its mount point. Each pass writes a small manifest at the destination; its outcome is shown in the bottom bar, and the Cleanup Session preview now says whether the raw DICOMs it is about to delete are in a complete backup newer than the last step. Engine in the new stdlib-only `pineuro.backup` module.
- **The RIT instructions can name the response keys after the study's button box.** The RIT localizer and RIT Experience Sampling instruction slides call the keys "button <key>" (e.g. "button 1"), which means little to a participant holding a button box. Each task now has three text settings in the Study Editor, `left_key_label`, `right_key_label` and `confirm_key_label` (e.g. "index finger", "middle finger", "thumb"), that the instructions use in place of "button <key>". Left blank, the default, the instructions are unchanged.

### Removed

- **`EventRelatedDesign` is removed; event-related paradigms run under `nuisance_only`.** The online GLM does not model event onsets, since the design matrix is built before the run starts. The class was implemented in `tasks/designs.py` and publicly exported, but no `design_type` value ever selected it and nothing constructed it outside a shape assertion in `tests/tasks/test_designs.py` — the only way to reach it was to pass an instance directly to `run_feedback_task`, which duck-types anything with `compute_regressors`. It was also the weakest form of the feature it named: it quantized onsets to whole TRs and convolved at TR resolution, where the block path convolves at 16 Hz and downsamples, so sub-TR onset timing — the entire point of an event-related design — was discarded. Rather than ship a method that would need rewriting, the limitation is now stated explicitly in the task-authoring guides, the `design_type` docstring, and the feedback-tasks documentation. Nothing is lost in practice: `design_type`'s two remaining values cover every built-in task, a trial-level paradigm runs as `nuisance_only`, and event-related **localizers** are unaffected — `mask_extraction_task` still fits a nilearn first-level model from a BIDS events file with arbitrary contrast expressions.

### Fixed

- **Localizer-only sessions now run preprocessing and mask extraction.** A session with localizer tasks but no feedback task collected the localizer data and then reported itself complete: preprocessing, mask extraction, approval and coregistration never ran, and the Mask Extraction section was hidden, so the masks a later feedback session reuses were never produced. Such a session now runs the full localizer pipeline, with only the real-time reference and feedback steps depending on a feedback task, and the Mask Extraction section shows whenever the session computes masks (a fresh or manual localizer, or MNI-atlas mode).
- **Documentation claims that contradicted the source are corrected.** Ahead of the public release, every user-facing claim was checked against the code. The real-time GLM's drift regressor is a **linear ramp** (one column, the volume index), not the "3rd-order polynomial" the feedback-tasks page described. WM/CSF nuisance masks come from **templateflow `MNI152NLin2009cAsym` tissue probability priors** warped into subject space, thresholded at p >= 0.9 and adaptively eroded — not from "ANTsPy tissue segmentation"; the mask-extraction page now documents the actual four steps. The task reference was stale in four places: RIT Triggered Ball requires **one** network with three optional roles (not three required) and its trigger parameters were renamed some releases ago (`trigger_threshold` → `activation_threshold`, `cooldown_duration` → `min_prompt_interval`), RIT Experience Sampling carried the same two stale names, the Gauge table listed a `baseline_duration` parameter that does not exist and two network *roles* as if they were parameters, and the RIT Localizer table listed three parameters under superseded names while omitting nine. The two RIT tasks' shared trigger gates are now documented once. The pipeline overview now states positively that real-time volumes are read directly with pydicom and never pass through dcm2niix, which four `feedback.py` docstrings still claimed; the timing key `dcm2niix_ms` is renamed `volume_read_ms` to match what it measures. The repository URL in `pyproject.toml`, `README.md`, `CONTRIBUTING.md`, `docs/index.md`, and the installation guide is corrected to the git remote, `github.com/WhitfieldGabrieli-EPICBrainLab/pineuro`.
- **The validation suite's README no longer claims the suite has no soft floors.** It has exactly two, both `>= 0.5` correlation floors on ANTs motion output that assert pineuro's `.par` column layout and sign without asserting ANTs' recovery accuracy. The exemption was legitimate but undocumented, contradicting the README's blanket statement; the floors are now named and justified as a third documented tolerance pattern alongside *independent reference* and *exact invariant*. No test or threshold changed.
- **An unrecognized `design_type` no longer yields two different GLMs depending on how the run was launched.** The mapping from `TaskMetadata.design_type` to a task design existed in two places that disagreed on the fallback: `session.py` logged a warning and returned **no task regressor**, while the GUI's `pipeline_runner.py` fell through a bare `else` to a **block design**. The same task, with the same typo'd or unrecognized `design_type`, was therefore fit with a different design matrix from `run_single_task` than from the participant workflow, with only a log line to show for it. Both now dispatch through a single `designs.design_for_metadata()`, which raises `ValueError` naming the offending value and task — `design_type` is set in task code and never in user config, so an unrecognized value is a programming error, not something to paper over. `_compute_regressors_for_task` returns a `(n_volumes, 0)` array rather than `None` for nuisance-only designs, matching what the GUI has always passed and what `FeedbackEstimator` already treats as zero task columns.
- **The Task Display mirror no longer flickers.** The operator-facing mirror strobed for three independent reasons. (1) `ft.Image.gapless_playback` defaults to `False`, which "briefly shows nothing" whenever the image provider changes — and the mirror assigns a fresh base64 data URI ~15 times a second, so the widget blanked between every frame; it is now `True`, holding the previous frame until the next one has decoded. (2) The dead vector-mirror path (`get_mirror_state()` / `_emit_mirror_state()`, plus the ball/gauge/RIT-triggered-ball overrides) emitted a visual-state dict **every frame at ~60 Hz** through the same callback as the screenshots. In the task subprocess that callback is a `maxsize=1` latest-wins slot, so roughly three of every four screenshots were evicted before they could be sent — and what did arrive was discarded by the GUI anyway, since `TaskMirror` only renders `type == "screenshot"`. RIT Triggered Ball and RIT Experience Sampling were the only tasks still emitting it; the whole path is removed. (3) The feedback monitoring panel built its mirror unsized, so the container collapsed during each decode gap and reflowed the surrounding row; it now takes the same fixed dimensions as the localizer panel. Adds a test file for `TaskMirror`, which previously had none.
- **Button-box presses now reach the task window on macOS while the operator works in the GUI.** pineuro polls global key state so that scanner triggers and participant responses register while the stimulus window is unfocused, but the macOS backend has never run. Its focus check read pyglet's X11-only `_window` attribute (since v0.1.0), and since v0.10.0 it imported `kCGEventSourceStateCombinedTaskState`, a Quartz constant that does not exist — the session→task terminology rename rewrote `kCGEventSourceStateCombinedSessionState`. Both errors were swallowed. Instruction slides and the trigger still worked because a newly shown window has focus, but after any click in the GUI, presses went to the GUI until someone clicked the stimulus screen. The constant is restored, the focus check is replaced by the dedup the Wayland backend already uses (pump the window, then inject only presses pyglet did not deliver), and the active backend, or why polling is unavailable, is logged once at task start together with macOS's Input Monitoring status. The RIT localizer's ratings, thermometer ratings, the gauge catch trial, and self/other responses now poll as well — on every OS they previously required the stimulus window to have focus — and the RIT experience-sampling and post-run slider prompts now ignore a key still held from before the prompt appeared, as the instruction and trigger waits already did. The display-setup guide documents the macOS Input Monitoring permission.
- **The GUI no longer hangs at the end of a localizer run.** Once a localizer's collection ended, the GUI signalled the task subprocess to stop through a `multiprocessing.Event`, and `Event.set()` waits for every process blocked in `Event.wait()` to acknowledge its wake-up. The subprocess kept a stop-listener thread in `wait()` for the whole run, so if the subprocess had already exited on its own (a natural end, or ESC), `set()` blocked forever: the step never completed, Stop did nothing, no other step could start, and pineuro had to be restarted. Being a timing race, it struck intermittently and on every OS; a Stop that landed while the subprocess was exiting froze the whole GUI, because click handlers run on the Flet event loop. The stop, task-done and show-questions signals are now lock-free shared bytes (`SharedFlag`, a `RawValue`) that the subprocess polls, so signalling can never block. Teardown is bounded throughout: a feedback subprocess that has reported done gets the grace period to exit before it is terminated, the post-kill join and the file-watcher join take timeouts, and the message reader keeps draining until the subprocess has exited (so its queue can always flush) and logs a failing handler instead of stopping. The subprocess's simulator thread is now a daemon that `stop()` and `cleanup()` tell to stop; a Stop before a manual trigger previously left it waiting, holding the step until the 60 s watchdog fired. Each subprocess exit is logged with its exit code, and a teardown still running after 20 s writes every thread's stack to the session log. Adds a regression test that spawns a real child process.
- **RIT Triggered Ball now ends with the scan.** When the last volume arrived mid-episode, the task kept the episode running for up to its full `episode_duration` (30 s by default) after the scanner had stopped, and the final-volume update could even open a fresh episode. With no volumes arriving, the ball kept moving at its last speed and hits kept accumulating, all recorded as a complete episode, while the GUI step stayed "running". The run now ends at the last volume: an episode in progress is recorded as `ball_triggered_incomplete` / `ball_timeout_incomplete` with its actual duration, the run results report `n_episodes_incomplete`, and the task waits briefly for the final volume's activation so the events file is never a row short. RIT Experience Sampling still lets the participant finish a rating that is open when the scan ends; its docstring no longer claims it uses the base run loop.
- **The scanner-connection status icon now changes with the result.** It was updated through `Icon.name`, a property flet 0.80 does not have, so only its color changed.
- **The scanner check now catches pineuro running under the wrong account.** With the Siemens BOLD Dot Add-In, the scanner writes each DICOM as the account named in the add-in's User Name, readable by that account only, so pineuro has to run under that account. The Network Testing guide said so, but nothing in the app caught the mistake, and a scanning session was started from a different login. On macOS and Linux, the scanner connection check (before every acquisition, and in the Scanner Connection test) now compares the account pineuro runs as with the account the scanner writes as, read from the newest entry in the watch folder, else from the folder itself or the parent folder that hides it, and fails with both account names when they differ. A watch folder pineuro cannot even inspect is now reported instead of letting the pre-run check proceed without a warning; permission errors on the folder point to the account requirement on every OS; and the Installation guide states the requirement where operators start.
- **Two localizers in a session can no longer claim the same mask name.** Every fresh localizer's thresholded masks are copied into one shared `03_masks` folder named only by mask name, so a second localizer producing, say, `DefaultA` silently overwrote the first one's mask; the real-time coregistration then registered the surviving file with the *first* localizer's transform and skipped the second as already done, leaving a mask aligned to the wrong reference with nothing logged. Coregistration also selects a localizer's files by `{name}_` prefix, so `Trigger` from one localizer picked up `Trigger_left` from another, and a mask a feedback run reuses from an earlier session resolved to the same coregistered file as a same-named mask produced fresh in the session. The study editor now refuses to save such a protocol and `StudyConfig.build_session_config` raises on it (catching hand-edited YAML), naming the mask and the localizers involved (`gui.utils.mask_name_collision_error`). Relatedly, `localizer_mask_names` now reports a task localizer's registered default contrasts when its config lists none, as mask extraction already used them, so those masks are validated and are no longer skipped by coregistration.
- **No more FSL or system-package install advice.** `check_platform_requirements()` told users to install dcm2niix with apt, brew or winget, although dcm2niix has been a pip dependency since FSL was dropped; it now says to run pineuro from its own Python environment (whose scripts folder holds the pip-installed dcm2niix) or to `pip install dcm2niix`. Docstrings that still described FSL commands (`mcflirt`, `fslcc`) as part of the pipeline now describe what actually runs: dcm2niix as the only external command, numpy for spatial correlation, and ANTsPy motion correction writing mcflirt-format `.par` files. `_check_command_installation` defaults to `dcm2niix` instead of `fsl`.

## [0.11.2] - 2026-06-04

### Breaking

- **The `inverse_sd` ROI-combine method is renamed to `voxel_efficiency`.** The Hinds et al. (2011) `1/σ` efficiency weighting is now named after what it does rather than how it is computed, matching the name already used in the docs and GUI help. `roi_combine_method` configs carrying `inverse_sd` no longer validate — `FeedbackRunConfig.VALID_ROI_COMBINE_METHODS` and `ROI_COMBINE_METHODS` accept only `voxel_efficiency` and `mean` — so existing study YAMLs must be updated to `voxel_efficiency` (active studies in `~/.pineuro/studies/` were migrated out of band). The GUI dropdown label drops the citation and reads "Voxel efficiency weighting"; the math, defaults, and the `mean` option are unchanged.

### Added

- **Scanner triggers and advance keys now reach the stimulus window under Wayland.** The unfocused-key polling that lets the stimulus window receive scanner triggers and advance keys while the operator is focused on the control monitor previously used X11 `XQueryKeymap`, which returns all-zeros under Wayland whenever a native window holds focus (XWayland only sees keys the compositor forwards). pineuro now reads `/dev/input/event*` directly via `evdev` — the kernel layer, below the compositor — when `is_wayland()` is true, falling back to X11 on Xorg. Because `evdev.list_devices()` filters candidates with `os.access`, which ignores the systemd-logind `uaccess` ACLs granted to the active local user, the device nodes are globbed and opened directly so ACL-granted keyboards are seen; a genuine permission problem now surfaces as a `PermissionError` with an actionable input-group hint. An XWayland focus query proved unreliable (it could report our window focused while a Wayland-native control window held focus, dropping every trigger), so it is replaced by a dedup that pumps the pyglet window and injects only the keys pyglet did not already deliver, never double-advancing a slider. `is_wayland()` also honors `WAYLAND_DISPLAY` (a spawned task subprocess may not inherit `XDG_SESSION_TYPE`). Adds the Linux-only `evdev` dependency and declares `python-xlib` explicitly; running under Wayland requires the user to be in the `input` group, now documented authoritatively in the display-setup notes.
- **Configurable trigger conditions for RIT tasks.** RIT Triggered Ball and RIT Experience Sampling replace the hardcoded `activation > 0 AND slope > 0` trigger with four independently toggleable condition gates — activation level, slope/trend, mean-over-window, and sustained count — each with a configurable threshold and combined by an all/any (AND/OR) selector. Defaults reproduce the original behavior exactly, so existing study configs are unaffected; a cross-parameter validator rejects "no condition enabled" and `count_min > consecutive_volumes`, and the per-volume log suffix shows only the enabled gates plus the combine mode. The design is implemented separately in each task file, keeping the tasks independent plugins.

### Changed

- **PsychoPy task steps now run in fresh subprocesses.** Each localizer/feedback step runs in its own spawn subprocess (`tasks/subprocess_runner.py`) so pyglet/GL/Cocoa state cannot leak between PsychoPy windows — fixing the macOS `ObjCInstance/initWithWindow_` crash on the second task of a session and the equivalent Windows relaunch crashes, since each process now creates exactly one window. The coordinator and task run in the child via `run_feedback_task`/`create_task`; the parent drains progress/mirror/log/result/error over a queue and keeps `collect_volumes` for localizers. `MainThreadDispatcher` is retained only for the Windows/Linux tkinter file pickers. The `siemens_moco` dual-series transfer is now logged once per run instead of every TR.
- **Default rest-localizer network order flips to `["ContA", "DefaultA"]`.** Dual-network tasks (ball, gauge) with no explicit `network_assignment` fall back to the localizer's `networks` order (positive = `networks[0]`, negative = `networks[1]`), so the differential contrast is `networks[0] − networks[1]`; ContA first now yields the intended `ContA − DefaultA` (ball moves up when attention/ContA exceeds DefaultA), matching the task intent and existing test fixtures. Updates the canonical `LocalizerConfig.networks` default, the GUI new-localizer templates, and the display/extraction fallbacks; saved studies store networks explicitly and are unaffected.
- **Localizer "motion correction" renamed to "motion monitoring".** The localizer setting only selects how motion parameters are estimated for real-time QC display during collection — it never realigns volumes (motion correction always happens post-hoc in preprocessing step 02). The misleading UI label and the `LocalizerConfig.motion_correction` config key (and the `CollectionQCMonitor` param it feeds) are renamed to `motion_monitoring`. The feedback-tab `GLMConfig.motion_correction` field is genuinely corrective — it selects the series/registration feeding the real-time GLM — and is left unchanged.
- **Feedback task config panel mirrors the localizer tab.** Baseline volumes and motion correction move into Scan Parameters, FD/DVARS/tSNR move into a new Quality Control section (with the localizer's caption), and the real-time GLM nuisance regressors and smoothing stay under Real-Time Processing. Layout-only change in `build()` — field creation and `collect_config()` are unchanged, so config persistence is unaffected — and it applies to all feedback tasks.
- **Tightened caption spacing across the Study Editor.** `styles.caption()` now returns a `Container` with a negative top margin so muted helper/hint text sits closer to the preceding section header or field, reading as a tight subtitle rather than an independently spaced row; redundant `Divider`s after several section captions are removed. Call sites that mutate caption text at runtime now write through `.content.value`.
- **Documentation: pineuro must run as the SMB user the scanner writes as.** The Siemens BOLD Dot Add-In writes each DICOM to the share owned by the configured User Name, granting `rwx` to that account only. The requirement to run pineuro logged in as that same dedicated user is now documented across all platforms, correcting the macOS instructions that previously said logging into the account was unnecessary.

### Fixed

- **Real-time tSNR/DVARS QC: masking, standardization, and censoring.** Localizer tSNR/DVARS were computed over the whole raveled image including background air, so the value tracked the field of view rather than tissue and dipped below threshold on clean data; the running tSNR was also cumulative, so a transient motion spike permanently inflated accumulated variance and depressed tSNR for the rest of the run; and DVARS was compared raw (~12–19 intensity units) against a "standardized" 1.5 threshold, making it meaningless. tSNR/DVARS are now computed over a fixed intensity-gated in-brain voxel set derived from the first volume (also dropping mosaic gaps); DVARS is standardized in the compute layer by the running median of prior raw DVARS (clean volume ≈ 1.0; 1.5 = 1.5× typical, scale-free); and volumes exceeding FD/DVARS are censored from the tSNR estimate in both the collection and feedback paths, so a spike never enters the variance. Localizers gain their own configurable `qc` block (`localizers[*].qc`) and Localizer-tab fields, so collection plots/monitor read localizer thresholds instead of the feedback-only fallback.
- **Orphaned stop-watchdog timer could kill a later feedback re-run.** `PipelineRunner.stop()` armed a 60s `threading.Timer` watchdog that was never stored or cancelled, and its callback terminated whatever `self._current_process` happened to be at fire time. Stopping run A and re-running within the grace window let A's orphaned timer force-terminate run B's subprocess mid-acquisition (logged as "did not stop within grace period" + "Processed 0 volumes"), intermittently depending on timing. The watchdog is now bound to the process active when `stop()` was called and the timer is tracked and cancelled when the child exits, so no leaked timer thread lingers.
- **Misleading hardcoded "25%" in BallTask GUI hints.** The min/max-hits threshold hints claimed a fixed 25% scale adjustment, but the actual change uses the configurable `scale_adjust_factor` (default 0.25). The hints now reference the adjustment factor so they stay accurate when the parameter is changed.

## [0.11.0] - 2026-06-01

### Breaking

- **Per-session protocols with cross-session mask reuse.** A study now declares an ordered `sessions` list, each session carrying its own localizers and feedback tasks, instead of one flat protocol copied to every session — two sessions with the same scans are configured independently. Cross-session mask reuse is a property of **feedback runs**: `FeedbackRunConfig` gains `mask_sources` (mask name → source `ses-NN`), so a feedback-only session can source e.g. `ses-01`'s Trigger mask without re-declaring that localizer, and `build_session_config` synthesizes the reused localizer per source/producer so the per-localizer coregistration loop is unchanged. Tissue (WM/CSF) masks are cross-session aware — a source session extracts them when a later reusing session needs nuisance regressors. One source per mask name is enforced, and every referenced mask must resolve to a producing session. Existing studies in `~/.pineuro/studies/` were migrated to the sessions shape out of band.
- **`task_id`s are now BIDS-safe (no underscores).** `task_id` is interpolated into output filenames as `task-{task_id}`, where an underscore produces an invalid BIDS entity (e.g. `task-self_other`). Renamed `self_other` → `selfother`, `rit_triggered_ball` → `rittriggeredball`, and `rit_experience_sampling` → `ritexperiencesampling` at each task's metadata / class-attr / `register_task_class` sites, plus string-literal lookups in tests and docs. Files now use `task-{task_id}` for feedback runs and `task-{task_id}transfer` for transfer runs, with run numbers restarting per task (e.g. `task-ball_run-01/02`, `task-balltransfer_run-01`, `task-gauge_run-01`), matching the convention already used by localizers/collection/reference. A new `build_feedback_steps()` in `gui/utils.py` is the single source of truth for step ordering, task entities, and per-task run numbering.

### Added

- **Configurable single/dual ball movement for RIT Triggered Ball.** The default single mode drives the ball from the trigger (rumination) network's signed activation — negative moves up, positive moves down (`movement_direction`) — and the movement network defaults to the trigger but is overridable; dual mode keeps the legacy two-network difference. `NetworkRole` gains generic `optional` / `default_from` / `visible_when` fields and supports a single-mask (`n_networks = 1`) assignment, which the session resolver and pipeline runner now accept.
- **Triggered-episode durations in the feedback QC report.** RIT Experience Sampling and RIT Triggered Ball fire activation-triggered episodes whose durations were recorded in the BIDS events TSV but never surfaced. The Activation Timeseries section now overlays each episode window on the activation plot (colored by triggered / timeout / incomplete) and lists per-episode durations in a table below it. Tasks opt in via a new `TriggeredEventReport` declared on `TaskMetadata` (mirroring `live_metrics`); `qc.py` reads it generically with no `task_id` branching, so block-design tasks are excluded automatically.
- **Triggered-episode overlay on the post-run Feedback Summary plot.** For RIT Experience Sampling and RIT Triggered Ball, the Feedback Summary dialog now overlays the windows in which triggers fired on the activation timeseries (computed from the task's `TriggeredEventReport` spec and the run's events TSV), matching the full QC report instead of drawing only baseline shading and per-mask traces.

### Changed

- **The Study Editor is now a master-detail session workspace.** The flat tab bar — which silently re-scoped to the session picked inside the Study tab, making two sessions with the same scans indistinguishable — is replaced by a persistent left sidebar (scope list) plus a right detail pane. The sidebar lists "Study-wide settings" plus one row per session, each showing a protocol fingerprint (e.g. "Rest; Ball", or "Rest; Ball ← ses-01" when a feedback run reuses an earlier session's masks). You switch sessions from anywhere, the open sub-tab index is preserved across switches (compare the same localizer across sessions), and a banner names the active session above its Protocol / Localizer / Feedback tabs. Config is split by where it is stored: study-wide (name, paths, scanner, reference, display, simulator) behind "Study-wide settings"; per-session protocol on the session pane. The standalone Study and Paths tabs are gone. The `sessions` / `mask_sources` data model is unchanged.
- **New studies and sessions now start from a blank slate.** A new study (and a newly added session) starts with no localizers and no feedback runs, and the study name, example participant ID, and base directory start empty rather than prefilled. Scanner trigger keys and other study-wide settings are unchanged; save-time guards still require a study name and at least one task per session.
- **`=` is accepted directly as a scanner trigger key.** PsychoPy reports the `=` key as the event name `"equal"`, so configs previously had to carry the word `equal`. `TaskBase` now owns trigger-key resolution — it holds the single default `["t", "+", "5", "="]` and normalizes `"="` to `"equal"` at runtime — and leaf tasks no longer declare `trigger_keys` (also fixing a thermometer/gauge post-`super()` overwrite). Config, GUI, and docs default to `"="`; existing studies were migrated (`equal` → `=`).
- **RIT localizer defaults to a single run.** A task-driven `default_n_runs` field on `TaskMetadata` (default 2) is set to 1 for the RIT localizer, applied by the type-change handler off any `task_id` branch. The baseless `localizers[0].n_runs >= 2` validation rule is removed — single-run localizers preprocess and run ICA/GLM fine — while the positive-int check still enforces `n_runs >= 1`.
- **RIT localizer rating timeout lowered to 5s and rating keys standardized.** The default `rating_timeout` drops from 15s to 5s, and rating navigation keys are standardized to left = `1`, right = `2`, confirm = `0` across the RIT localizer and RIT experience sampling.
- **The RIT trigger log suffix now explains the trigger decision.** The old `slope -0.154 (n=2)` suffix saturated and carried no information about the instantaneous AND of the threshold and trend gates; it is replaced by a gates-and-verdict suffix (trend gate, threshold gate, cooldown / warmup) driven through a single `_evaluate_trigger()` shared by the real trigger and the log formatter, so the log can never disagree with the actual trigger.
- **Sham configuration UI is gated on the study-wide Enable Sham switch.** With sham disabled, the Study tab hides Blind Mode and the randomization-file row and each feedback tab hides its entire Sham Mask Construction section; a disabled study also stops persisting a per-run sham block, so non-sham studies no longer save meaningless construction defaults.
- **Inert DEBUG logging removed; three traceability gaps closed.** GUI DEBUG was filtered out at the logger gate and written nowhere, so every `logger.debug` call was inert; the calls are removed (a few promoted to INFO/WARNING) and the session-file handler set to INFO. Alongside: a software motion-correction shape mismatch now aborts the run instead of falling through into registration, parallel-worker exceptions carry a traceback across the process boundary, and `TaskState.save()` guards its write.
- **Cross-session mask reuse now requires the real-time reference.** A feedback run that sources a mask from an earlier session (`mask_sources`) needs the real-time-reference coregistration to bring those masks into the current session's space, which is gated on `reference.realtime_enabled`. The incoherent combination (reuse on, real-time reference off) is now rejected up front in both the study editor and the runtime, instead of failing cryptically with a missing-mask-file error against the empty current-session mask dir.
- **Reference-scan simulator DICOM paths are now per-session and content-gated.** Each session replays its own recorded initial / real-time reference acquisition, so those source-DICOM fields live on the session's Protocol tab rather than study-wide, and each is shown only when the active session actually performs the matching acquisition (initial reference for fresh localizer masks, real-time reference before feedback).
- **Localizer thresholding UI tidied.** "Thresholding method" now sits above "Voxels per mask", and the voxel-count field is hidden for `cluster_extent` (which is driven by stat threshold + min cluster size + optional max-total-voxels, not a voxel count).

### Fixed

- **`siemens_moco` selected against non-MoCo data silently reported success.** In `siemens_moco` mode the coordinator keeps only MoCoSeries volumes and skips every original; with non-MoCo data all volumes were skipped, `n_processed` stayed 0, and the run reported success with an empty feedback log. It now fails with an actionable message once the skip threshold is reached, and any feedback run that processed 0 volumes (unless user-stopped) is failed instead of masquerading as success.
- **Stray non-volume files corrupted directory enumeration.** `get_volume_files` / `get_dicom_files` now validate each file's header and skip stray non-volume files (`.DS_Store`, `Thumbs.db`, sidecars, scanner junk), logging what was ignored. This closes the gap where `VolumeSimulator` trusted the raw listing — a stray first-sorted file like `.DS_Store` was used as `volume_files[0]` for source-type / TR detection and copied downstream — and lets the simulator distinguish an empty source dir from one holding only non-volume files.
- **macOS GUI hung when opening file/folder pickers.** tkinter dialogs hang on macOS because `ft.app()` runs in a background thread while the main thread runs a bare queue loop with no Tk/Cocoa event loop (Python #38974), and `ft.FilePicker` is broken in flet 0.80.5. Native `osascript` dialogs (`pick_file` / `pick_directory` / `pick_save_file` in `gui/utils.py`) are now used on macOS, keeping the tkinter dispatcher path on Windows/Linux; all picker call sites route through them.
- **RIT memory passes were non-complementary across sessions.** RIT runs once per session, but localizer run numbers are session-scoped, so every single-run session saw `run_number == 1` and drew the same memory pass. A new study-wide `total_runs` parameter packages the cross-session run count; each run's pass is now chosen from a cross-session view (the next pass the participant has not used across all of their sessions), keeping passes complementary and deterministic per participant even if sessions run out of order. `total_runs == 1` skips the lookup; `target_pass` / `pass_window` are persisted and restored unchanged on retry.
- **`last_feedback_only` questions fired per session instead of per task.** The gate compared a session-wide `feedback_run_count` to a session-wide `max_feedback_runs`, so in a multi-task session (e.g. ball ×3 then thermometer ×2) the earlier task's `last_feedback_only` questions never fired. The per-task last-feedback-run decision now lives in the runtime layer that owns the run sequence and is set on the task per block, so each task's questions fire at the end of its own feedback block.
- **The stop-dialog "Show post-run questions" checkbox appeared for tasks with no questions.** It now queries the live task at stop time (via `PipelineRunner`) and hides the checkbox and help text when nothing is eligible, matching exactly what the stop path would display.
- **The feedback Task Type didn't propagate to the Feedback tab.** The Study Editor stored the task under the key `"task_type"` while the tab builder, validation, workflow, and runtime `FeedbackRunConfig` all read `"task"`, so selecting a non-default feedback task updated only the tab label and never persisted. Canonicalized on `"task"` at all six sites; also fixes a load-time bug that mislabeled a saved non-ball task as "Ball".
- **Study-configurator values were silently overwritten at runtime.** Three disagreeing default sources (editor templates, `session.py` dataclasses, inline `pipeline_runner` reads on a sparse config) let editor values be ignored or re-defaulted. `ShamConfig` is split into study-wide gating (`enabled` / `blind_mode` / `randomization_file`) and a per-run `ShamRunConfig` (construction); `use_transfer_runs` resolves its unset default from task metadata; connectivity fails loud when no configured pair references an available mask; and ICA `n_components` (30), simulator `feedback_speed` (1.0), and rest-extraction `smooth_fwhm` / `highpass` defaults are unified instead of raising `KeyError` on a sparse block.
- **GUI screen imports eagerly loaded numpy / pandas.** Importing a GUI screen pulled in numpy (and pandas / pydicom for the participant-workflow screen) through `tasks/__init__.py` and two components, violating the lazy-import rule. The heavy imports are deferred behind package `__getattr__` / PEP 562 and moved into the functions that use them (participant-workflow import 2.5s → 0.8s); a regression test guards it.
- **GLM mask-extraction panel ignored the threshold method.** The pipeline panel hard-coded `'{threshold} voxels'`, so `cluster` / `cluster_extent` configs displayed misleadingly (and `threshold` isn't used by `cluster_extent`). A shared `_format_threshold_summary` is used at both display sites; this also fixes `_get_step_info` reading `threshold` / `threshold_method` from the wrong dict nesting level.
- **Study Editor dropdowns didn't fill their row.** The responsive-form migration stripped explicit widths, but a Flet 0.80 Dropdown sizes to its content unless given `expand=True`, so every dropdown collapsed to the width of its longest option next to the filling text fields. The fill is centralized in `styles.py` (`colspan()` and a new `fill_dropdown()` helper).
- **Study Editor opened on `ses-01` instead of study-wide settings.** It now opens on the study-wide scope.
- **Per-session-protocol studies misread mask status.** The session mask-status helpers now recognize both the flat `03_masks/.masks_approved` layout and the per-localizer `loc_*/` layout, so `has_masks` / `masks_approved` no longer read False for per-session-protocol studies (used in both the status label and `detect_existing_sessions`).

The parenthetical is dropped from every "Review Masks" button so they read uniformly.

Coregistration now includes the sham construction networks.

Plot artifacts are now keyed by attempt and always regenerated from the resolved latest feedbacklog.

Over-cap results now keep the highest-stat voxels (exact top-N), never emptying a strong map.

### Fixed

- **GUI launched the wrong task on migrated study configs.** The participant workflow and pipeline runner still read the removed legacy top-level YAML blocks (`scan`/`mask`/`feedback`/`task`/`localizer_task`), so on a migrated config every read fell through to defaults — most visibly launching a rest task instead of the configured RIT localizer. ~50 reads were swept to the new `localizers[*]` / `feedback_runs[*]` / top-level `simulator`/`scanner`/`reference` schema.
- **Participant-workflow paths dropped the session component.** Step-completion detection, QC-report lookup, mask-extraction inputs, and feedback-log paths were built from a bare `participant_id` without `ses-XX`, so preprocessing never registered COMPLETE (locking mask extraction), mask extraction could not find its input, and several status globs / QC / feedback-metric lookups silently missed their files. All now use the consistent `{participant}_{session}` BIDS prefix.
- **`preprocessing(overwrite=True)` left stale `01_nifti/` files.** `dcm2niix` appends a letter suffix on filename collision rather than overwriting, so the canonical path kept old data while fresh output sat beside it with a suffix and downstream steps silently consumed the stale file. Prior outputs for the current label (primary, suffixed, multi-echo/phase splits, sidecars) are now removed first.
- **Stopped runs stayed PENDING instead of INTERRUPTED.** The feedback-slot status glob still used the pre-`ses-XX` filename pattern, so stopped feedback/transfer runs never matched and missed their INTERRUPTED (caution) flag.

## [0.9.0] - 2026-05-22

### Added

- **Manual Mask Import localizer type.** Researchers can supply pre-built, participant-specific NIfTI masks (native/EPI, T1, or MNI space) for neurofeedback instead of running ICA (rest) or GLM (task) extraction. The study config holds only participant-agnostic data (mask space, network names); each participant's mask / reference-EPI / T1 files are selected in their workflow and persisted per-participant to `manual_masks.json`. `import_manual_masks` supports opt-in QC reporting, and the pipeline runner imports the masks into `03_masks/`, generates QC, and coregisters them.
- **Validation suite** (`tests/validation/`) — a scientific-correctness test layer, separate from the regression suite, that runs synthetic phantoms with known ground truth through the real pipeline (real ANTsPy/nilearn, no mocking) and asserts the outputs recover that ground truth: HRF/design math, the incremental-GLM solver, ANTs motion correction & brain extraction, nilearn ICA & GLM task-mask extraction, real-time feedback signal recovery, and an end-to-end chained pipeline test. Includes a self-contained synthetic-data phantom library and a markdown/HTML metrics report. Opt-in locally (`pytest -m validation`); runs as a hard correctness gate on every push in CI. See `tests/validation/README.md`.

### Changed

- **Motion correction is now deterministic.** `motion_correction()` seeds ANTs' rigid-registration metric sampling (new `random_seed` parameter, default `0`), so re-running preprocessing on identical input yields identical motion parameters. Previously the metric's random sampling was unseeded, giving small run-to-run variation.
- **The RIT localizer's per-participant randomization is now reproducible.** It seeded its RNG with the builtin `hash()`, which is salted per process (`PYTHONHASHSEED`) — the same participant got a different trial order on every run. It now derives the seed from a stable `hashlib` digest.
- **`pineuro.__version__` now reflects the installed package metadata** (via `importlib.metadata`) instead of a hardcoded string, which had drifted to `0.2.0`. It can no longer go stale.
- **`pipeline_runner` no longer special-cases task IDs.** The fixation localizer's parameter handling branched on `task_id == "fixation"`; that decision now reads a `TaskMetadata.localizer_params_from_scan` flag, so fixed-duration localizers work without editing shared GUI code.
- **FD/DVARS/Siemens-MoCo motion parsing deduplicated.** Framewise displacement, DVARS, and Siemens MoCo motion-string parsing were copy-pasted between `feedback.py` and `collection_qc.py`, so a fix to one copy would silently not reach the other. `compute_fd`, `compute_dvars`, and `parse_siemens_motion_comment` now live once in `pineuro.utils`; both modules delegate to them.

### Removed

- **`tests/integration/` (Rockland_NFB real-data suite) and the `integration` pytest marker.** The preprocessing-pipeline, ICA mask-extraction, and feedback-estimation paths it exercised are covered by the synthetic-phantom validation suite; the marker and the `sourcedata/Rockland_NFB/` data dependency are gone. Note: real DICOM→NIfTI (`dcm2niix`) conversion no longer has dedicated test coverage.

### Fixed

- **ROI feedback weighting was inverted.** `FeedbackEstimator` weighted ROI voxels by their residual sum of squares (proportional to variance), *up*-weighting noisy voxels — a faithful copy of MURFI's `RtRoiCombine`, but the opposite of the Hinds et al. (2011) 1/σ efficiency weighting it was meant to implement. The `use_efficiency_weights` boolean is replaced by a `roi_combine_method` choice — `inverse_sd` (the corrected 1/σ weighting, now the default) or `mean` (unweighted) — routed through a single `_combine_roi` helper, with a study-editor dropdown and a migration shim for the old config key.
- **`script_generator` produced invalid Python on Windows.** Generated mask-extraction scripts embedded file paths via raw f-string interpolation (`Path("{path}")`), so a Windows path like `C:\Users\...` became a string literal where `\U` raised a `SyntaxError` and `\t`/`\m` etc. silently corrupted the path. Paths and the participant ID are now embedded with `repr()`, so generated scripts are valid on every platform.
- **The Self/Other localizer showed the wrong comprehension-question image** when the block order contained `rest` blocks. Questions were indexed by absolute block position, but the stimulus file holds only voice-block rows (5 per block); they are now indexed per voice block, so each voice block shows its own question.
- **GUI study-editor edits could mutate the source configuration.** The study editor and the localizer/feedback tab builders copied configs shallowly (`dict(config)`), so edits to nested blocks — including edits to a *duplicated* study — leaked back into the original. All config copies are now deep copies.
- **The feedback QC report crashed on logs missing optional columns.** It raised a `KeyError` when a feedback log lacked `dvars`/`tsnr` columns, and the ICA component-grid plot raised an `AttributeError` for a single component. Both are guarded, and reports no longer print `nan` for all-missing motion metrics.
- **Task-mask extraction could select a network from a `NaN` correlation.** The ICA spatial-correlation step divided by zero for a zero-variance component or an empty network mask; those cases are now detected and handled explicitly.
- **Resource leaks in the participant-workflow GUI.** The per-session log file handler was never removed or closed (handlers accumulated on the `pineuro` logger across sessions), and the feedback-monitor thread was not stopped when a pipeline step failed. Both are now cleaned up.
- **Numerous robustness fixes.** Runtime `assert`s used for input validation (silently stripped under `python -O`) are replaced with explicit errors; guards were added for empty `feedback_runs`, malformed session IDs, 3-D inputs to temporal filtering, empty ROI masks, and non-finite activation values; the task factory now verifies a registered task class subclasses `BaseTask`. The collection-run-number helper now matches the actual `acq-NN_run-NN` directory naming.

## [0.6.0] - 2026-05-04

### Fixed

- **Scanner trigger reliability**: Real scans occasionally never received the scanner's trigger keypress, leaving the task stuck on "Waiting for scanner...". Two intertwined causes are addressed.
  - The unfocused-window key-polling fallback (Windows `GetAsyncKeyState`, Linux `XQueryKeymap`, macOS `CGEventSourceKeyState`) had a one-shot seed-skip that silently dropped the very first detected press. Scanner triggers are short (~50-100ms) and the polling loop runs every 10ms, so the first detection was usually exactly the trigger itself. Replaced the seed-skip flag with a snapshot of currently-held keys taken at reset: a key already held must be released before its next press fires; a fresh press always fires.
  - The PsychoPy task window was never explicitly brought to the OS foreground when launched from the GUI, so pyglet's focused-event path silently failed unless the user manually clicked the task window. Added a best-effort window activation at the start of `wait_for_trigger`, including the `AttachThreadInput` Win32 trick that bypasses Win10/11's foreground-stealing block.
- **Diagnostics for trigger failures**: `wait_for_trigger` now logs the trigger keys, window handle, foreground state, keys held at reset, and which path delivered the trigger (`focused_event` / `poll_win32` / `poll_x11` / `poll_quartz` / `simulator_*`). Warns when a configured trigger key is missing from the active platform's keymap.

### Changed

- **Simulator trigger now exercises the real-scan code path**: previously the simulator bypassed the keyboard entirely by directly appending to PsychoPy's internal `_keyBuffer`, so simulator runs could never reproduce real-scan trigger failures. The simulator now routes through the same focus-dependent path as a real scanner, controlled by a new `scan.simulator_trigger_mode` setting in the study editor:
  - `manual` (default): simulator waits for the operator to press the trigger key, identical to a real scan.
  - `os_key`: simulator injects a synthetic OS-level keypress via `SendInput` (Windows), `Xlib.ext.xtest.fake_input` (X11), or `CGEventPost` (macOS). Pure-Wayland sessions and macOS without Accessibility permission automatically fall back to manual mode with a clear warning.
